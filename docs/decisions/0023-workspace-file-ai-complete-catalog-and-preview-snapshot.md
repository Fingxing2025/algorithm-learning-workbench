# ADR-0023：总体文件 AI 完整目录、预算与发送快照

- 状态：已接受
- 日期：2026-07-23
- 范围：总体文件 AI 管理的上下文、发送预览、隐私和计划审查

## 背景

总体文件 AI 管理仍使用早于 ADR-0022 的目录摘要：稳定前缀最多 80,000 字符，每个目录只列 12 个代表模板；随后再把审计和相关性候选限制为 250 个。发送预览与正式生成会各自重新审计、读取文件和组装输入，因此用户确认的内容不一定就是 Provider 收到的内容。现有实现还默认发送用户笔记，并把 SHA-256、修改时间和文件大小等仅供本地执行复检的数据放入模型 payload。

这些行为无法证明完整目录覆盖，也不能用真实输入预算解释降级或失败；元数据操作只展示标签和时间复杂度，用户也无法审查所有实际变化。

## 决定

1. 总体文件 AI 管理与新建模板、题目分析统一复用 `WorkspaceTemplateCatalog`。稳定上下文必须包含完整分级目录树，以及每份可用模板的稳定 ID、名称、工作区相对路径和语言。`relatedTemplates`、详细候选与源码片段只提供补充，不能代替完整目录。
2. 删除 300 个 catalog 模板和 250 个文件计划候选的产品级数量上限。准入只由确定性序列化后的总字符数和估算 Token 决定；正常的几百个短模板应一次完整发送。
3. 最小不可退化目录字段为模板 ID、名称、相对路径、语言和分级树。预算不足时，依次缩短摘要、省略 catalog 附加元数据、省略或缩短源码片段，再省略非审计相关的可选详细候选。审计范围的详细候选不能静默省略；最小完整目录或必需审计上下文仍超预算时，在网络请求前返回 `AI_CONTEXT_TOO_LARGE`。
4. 文件计划输入预算统一覆盖稳定 catalog、相关上下文、审计 JSON、候选路径/语言/元数据、用户笔记、源码片段、system prompt、JSON Schema/结构化输出说明和固定协议开销。输出上限仍为 5,000 Token；Provider 的有限输出预算与结构化输出降级协议不变。
5. `previewFilePlan` 在 Main 内存创建短期、一次性 `FilePlanInputSnapshot`，返回独立 `previewId`、`expiresAt`、输入 SHA-256 和完整统计。快照保存最终 system/text/stable context、Provider/模型指纹、工作区版本、候选本地前置条件和隐私选项；不写 SQLite、不跨进程重启恢复。
6. `generateFilePlan` 只消费 `previewId`，不得重新组装另一个输入。发送前复检活动工作区、Provider/模型、完整目录版本、catalog 路径/大小/修改时间，以及候选 SHA-256 和元数据版本。快照过期、重复消费、跨工作区使用或任一复检失败时拒绝发送并要求重新预览。
7. 用户笔记默认不发送。只有用户明确开启时，才把详细候选中的非空 `notes` 放入 payload，并在预览中显示笔记数量与字符数；笔记纳入总预算。关闭时 catalog、相关上下文和候选元数据均不得包含 `notes`。
8. SHA-256、mtime、大小、数据库/备份路径、工作区绝对路径、密钥引用、API Key、自定义鉴权头和错误日志都不进入 Provider payload。SHA-256、mtime、大小只驻留 Main 快照，用于发送前和执行前复检。
9. 元数据更新操作可新增向后兼容的可选 `previousMetadata` 快照。新计划保存完整旧值，Renderer 只展示发生变化的字段，覆盖 `solves`、`constraints`、`prerequisites`、`commonMistakes`、时空复杂度、标签和笔记；笔记变化保持高风险。旧版 operations 数组和没有旧值快照的 V2 计划继续可读，并以兼容提示展示。
10. 所有删除操作默认不勾选，包括本地确定性完全重复删除；AI 高风险操作也默认不勾选。移动/删除资格、授权路径、扩展名、目标冲突、用户逐项选择、二次确认、操作前备份、失败补偿回滚、执行后重扫和撤销前外部修改检查均保持不变。
11. Main 在预览和正式创建前都检查活动草稿，并阻止同一工作区并行生成多份草稿。单计划继续最多 100 项；本地与 AI 操作合并后可能超限时，必须返回包含覆盖范围和下一步的明确错误，不能让最终 Zod 解析意外失败，也不能静默删除操作。
12. 候选源码读取失败进入快照诊断和预览统计。重复/相似审计组超过路径展示上限时显式返回总数与截断标记；Renderer 显示“已展示/总数”。当前审计能力继续保留 `stale-relation`，实现必须与合同和能力说明一致。

## 兼容与后果

- 本决定修改命名 IPC 的 Zod 输入/输出契约，但不新增数据库列或 migration；快照只在 Main 内存中存在。
- `operations_json` 仍使用版本化 envelope；新增操作字段为可选，旧数组格式和旧 envelope 均可读取。
- 更大的完整 catalog 会增加请求体；估算 Token 是保守预算，不是供应商窗口的官方保证。Provider 仍可能返回其自身的上下文上限错误。
- 取消、预览过期、发送前复检失败、无效 AI JSON和生成失败都不创建计划、不修改文件。
