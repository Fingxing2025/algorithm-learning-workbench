# ADR-0005：题目图文 AI 分析草稿

- 状态：已接受
- 日期：2026-07-14
- 范围：阶段 4

## 背景

用户需要通过题面文本、截图或粘贴图片生成题目卡片和候选模板关联。AI 输出不可信，也可能因模型能力、提示注入或响应格式异常而包含错误字段和不存在的模板 ID。取消分析不能留下题目、图片或关联数据。

## 决策

1. 分析流程分为“输入、分析草稿、用户确认”三步。分析和编辑期间，草稿只保存在 Renderer 内存，不写 SQLite 或题目图片目录。
2. 系统文件选择器只返回经过 Main 校验的 PNG/JPEG/WebP 数据和显示名称，不返回绝对路径。粘贴图片由 Renderer 读取后通过同一 Zod 数据契约提交。
3. 单次分析最多 6 张图片、每张 8 MiB、合计最多 24 MiB。Main 再次校验 data URL、解码大小和真实文件魔数，不能只信任 MIME 声明。
4. Main 根据 `problem-image-analysis` 任务路由选择 Provider。包含图片时必须验证 Provider 的视觉能力；没有已配置路由或密钥时返回可操作提示。
5. Main 只向模型发送用户明确输入的题面、所选图片和当前工作区的有限模板摘要。连接测试、日志和错误不包含这些数据。
6. Provider Adapter 接受统一的多模态请求，并映射为各协议的图文内容块。模型被要求返回 JSON；响应先经过大小限制、JSON 解析和 Zod 校验。
7. 模型输出的模板 ID 必须存在于本次发送的模板摘要中，否则丢弃。候选关系最多 8 项，默认类型为 `recommended`，来源固定为 `ai`。
8. 用户可以修改所有题目字段、取消候选关系或调整关系类型。只有点击“确认创建”后，Main 才写入正式题目、图片和关联。
9. 确认写入时，Main 先将经过复检的图片写入新题目目录，再在单个 SQLite 事务中创建题目、图片记录和 AI 关系；数据库失败则删除已写文件。文件写入失败时不创建数据库记录。
10. 阶段 4 不保存原始模型响应、提示词、思维过程或分析历史，也不生成学习诊断和算法讲解。

## 后果

- 取消草稿或关闭应用不会留下持久化数据。
- 为了让用户预览，Renderer 会短暂持有用户主动选择/粘贴的图片数据，但不会获得文件路径、Provider 密钥或直接网络权限。
- 大型模板库只向模型发送截断后的摘要；界面必须明确候选仅来自本次可见摘要，用户仍可在创建后手动添加其他模板。
- 阶段 5 若需要持久化 AI 文件计划，必须使用独立 schema 和确认/回滚语义，不能复用本阶段的内存草稿假设。
