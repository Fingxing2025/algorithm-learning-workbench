# 0011：界面国际化与工作台动效编排

## 背景

首版 Renderer 的简体中文文案分散在页面组件中，无法在不重载应用的情况下切换英文。工作台已有局部微交互，但页面进入、概览卡和列表的节奏没有统一；工作台内容超出可用高度时也没有形成可滚动容器。

## 决定

- Renderer 建立轻量类型化国际化层，首批 locale 为 `zh-CN` 与 `en`。
- 界面 locale 保存在 Renderer `localStorage` 的 `ui:locale` 中，同步更新 `document.documentElement.lang`；不新增 IPC、SQLite 字段或 migration。
- 翻译只作用于应用框架、功能页、对话框、空状态和可操作提示。用户题面、源码、路径、标签、Provider 名称和 AI 返回内容保持原文。
- 动态状态、选项数组、元数据字段和公开错误也必须经过同一翻译入口；带 HTTP 状态、数量或路径的公开错误使用受限模式翻译，变量原样保留。
- 文件只读审计不直接展示 Main 返回的中文 `kind/detail`，Renderer 根据结构化问题类型生成本地化标签与说明；路径仍保持用户原文。
- 源码完整性测试扫描 Renderer 生产字符串以及 Main/Preload 静态公开错误。新增中文界面词条但没有英文映射时，测试直接失败；真实 Electron E2E 另外扫描正文、placeholder、title 和 ARIA 标签。
- 界面 locale 与模板 AI 补全语言是两个显式选择：切换英文界面不会静默改变正在编辑的入库草稿。
- 工作台主内容建立明确的 `height: 100%` 滚动边界，导航、顶栏和底部运行状态保持固定。
- 概览卡使用真实按钮语义、可见焦点和明确的去向：模板、题目和待确认计划分别进入对应工作区。
- 动效使用 Motion variants 统一编排：页面进入约 380 ms，概览卡错峰 60 ms，小控件反馈 180–220 ms。不使用大幅弹跳或循环缩放。
- 使用 `useReducedMotion` 遵循系统偏好：减少动效时移除大区域位移和缩放，保留必要的透明度与状态变化。

## 后果

- 语言切换对应用文件零写入，不影响新老 V2 用户数据与模板文件。
- 新的用户可见文案必须通过国际化层添加中英文词条，并由测试覆盖切换和持久化。
- 英文页面中的用户内容可能仍包含中文，这是保留原文的预期行为；系统状态、错误、审计类型和控件文案不得借此豁免。
- 界面语言不改变已有题目、元数据和文件名；AI 补全仍以用户在当次入库流程中的语言选择为准。
