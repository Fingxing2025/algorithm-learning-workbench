# ADR-0002：模板工作区、SQLite 索引与只读扫描

- 状态：已接受
- 日期：2026-07-14

## 背景

阶段 1 要让全新用户创建或选择模板工作区，并从真实桌面入口完成只读扫描、模板树搜索和源码查看。该流程跨越系统目录选择器、文件系统、SQLite、IPC 与 Renderer，必须先固定授权和数据边界。

## 决定

1. 工作区根目录只能由 Main 进程通过 Electron 系统目录选择器获得。Renderer 只提交“创建空白工作区”或“选择已有目录”的意图，不提交任意绝对路径。
2. Main 将选择结果解析为真实路径并确认它是目录。扫描、源码读取、在文件管理器中显示和复制源码都只接收工作区或模板 ID，再从数据库解析路径。
3. 所有文件操作在执行前同时做词法路径检查与 `realpath` 检查；扫描不跟随符号链接，防止越过授权根目录。
4. 首版只识别常见源码扩展名；跳过隐藏目录、依赖目录、构建目录和符号链接。扫描深度上限为 24，模板数量上限为 20,000，源码读取上限为 2 MiB。
5. SQLite 保存工作区、模板索引、相对路径和扫描摘要，不保存模板源码。模板源码始终以用户文件为准。
6. 使用 Drizzle ORM 描述 schema，使用版本化 SQL migration 建库。migration SQL 作为只读字符串打包进 Main，并由本地 migration ledger 事务式执行，不依赖删除数据库重新生成。
7. 模板 ID 由工作区 ID 与相对路径生成稳定 SHA-256 摘要。Renderer 不使用绝对路径作为读取凭据。
8. 模板树在 Renderer 根据相对路径构建；只有单一子目录的连续层级可以折叠为展示路径，真实目录与数据库相对路径保持不变。
9. 大型树使用 TanStack Virtual 虚拟化扁平可见节点；键盘导航和搜索定位操作同一份展开状态。
10. 测试通过独立临时应用数据目录和临时模板目录运行，不读取或修改开发者的真实模板和 V2 数据。
11. 为满足空白工作区从零开始，阶段 1 提供最小手动新建模板：用户在确认面板中输入文件名和源码，Main 仅允许在当前工作区根目录创建一个受支持扩展名、最大 2 MiB 的新文件，并使用 exclusive create 禁止覆盖。AI 分类、批量上传、移动和覆盖仍留到后续模板入库阶段。

## 数据模型

- `workspaces`：ID、名称、授权根目录、创建与最近扫描时间。
- `templates`：稳定 ID、工作区 ID、相对路径、文件名、语言、大小和修改时间。
- `app_state`：当前工作区 ID 等非敏感应用状态。
- `app_migrations`：已经执行的 V2 schema migration。

## 扫描摘要

扫描结果至少包含模板数量、不支持文件数量、跳过的符号链接数量、大小写路径冲突数量、是否达到数量上限和有限数量的可操作问题。扫描不会自动移动、重命名、覆盖或删除文件。

## 后果

- 首次目录授权仍依赖用户操作系统对话框，Renderer 无法绕过该步骤访问其他目录。
- `better-sqlite3` 是原生依赖；本地开发和 CI 必须针对当前 Electron ABI rebuild，后续打包阶段还要验证 macOS 与 Windows 产物。
- 除用户明确确认的单文件新建外，阶段 1 的扫描和浏览保持只读。批量写入、元数据编辑、移动、覆盖、备份和回滚仍属于后续模板入库纵向切片。
