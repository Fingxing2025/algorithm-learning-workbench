# ADR-0038：动态暂存导入的持久化、审查与原子应用

- 状态：已接受（用户授权的 S1 整合切片）
- 日期：2026-09-14
- 基线：0d9789f；只读移植 c43d 未提交业务实现，原工作树完整保留。

## 背景与范围

批量导入需要逐项保留结果、失败续跑、重启恢复，以及明确的最终确认。此前元数据
补全与分类完成容易混同。本切片整合动态暂存；规范分类体系与评测工具由独立切片提供。
现有 ADR-0035 保持原样，不导入来源的发布脚本、Codex 配置或历史实施计划。

## 决定

1. 工作区 SQLite 增量 migration 增加暂存会话和条目；源文件只读复制到
   `.awb/staging/<id>/`。正式模板、元数据与题目关系在最终确认前保持不变。
2. 每项完成分类和文件持久化后才计入 completed/processedCount；仅有元数据不是
   分类完成。失败/取消保留已完成项，重试与继续幂等；重启可恢复未完成会话。
3. 所有操作经 typed Preload 和 Zod IPC；Main 解析当前工作区。任务绑定工作区、
   请求和版本，取消、切换与迟到响应不得污染新会话或已关闭数据库。
4. AI 只返回草稿。暂存审查使用完整目录作为上下文，只有当前批 actionable IDs
   可产生操作；跨批建议过滤并显式提示。所有文件操作先展示 Diff 再由用户确认。
5. 最终应用必须 confirmed: true，并复检工作区身份、源码树与数据库基线；备份、
   恢复 journal、目录交换和 SQLite 事务共同保护失败回滚及题目关联一致性。
   恢复失败保留证据，禁止自动清除。放弃只清理受管暂存目录。
6. 不增加依赖或 Provider 协议。保留已有批量 IPC 以保护现有 V2 行为；真实新桌面
   批量入口进入暂存流程。正式模板库 AI 不作为导入后的自动副作用运行。

## 验证与后果

新增数据结构只通过 migration 演进；空库与既有 V2 升级均测试。服务/数据库/
Renderer 回归覆盖逐项进度、迟到响应、跨工作区、审查和最终回滚；真实 Electron
用临时工作区与本地 mock Provider 验证确认、重启、亮暗截图。暂存复制增加磁盘占用；
只有用户放弃或成功应用后清理。S3 的规范分类结果需在后续组合时再次验收。
