# ADR-0038：动态暂存导入的持久化、审查与原子应用

- 状态：已接受（用户授权的 S1 整合切片）
- 日期：2026-09-14
- 基线：0d9789f；只读移植 c43d 未提交业务实现，原工作树完整保留。

## 背景与范围

批量导入需要逐项保留结果、失败续跑、重启恢复，以及明确的最终确认。此前元数据
补全与分类完成容易混同。本切片整合动态暂存；规范分类体系与评测工具由独立切片提供。
现有 ADR-0035 保持原样，不导入来源的发布脚本、Codex 配置或历史实施计划。

## 决定

1. 工作区 SQLite 增量 migration 增加暂存会话和条目；源文件只读复制到
   `.awb/staging/<id>/`。正式模板、元数据与题目关系在最终确认前保持不变。
2. 每项完成分类和文件持久化后才计入 completed/processedCount；仅有元数据不是
   分类完成。失败/取消保留已完成项，重试与继续幂等；重启可恢复未完成会话。
3. 所有操作经 typed Preload 和 Zod IPC；Main 解析当前工作区。任务绑定工作区、
   请求和版本，取消、切换与迟到响应不得污染新会话或已关闭数据库。
4. AI 只返回草稿。暂存审查使用完整目录作为上下文，只有当前批 actionable IDs
   可产生操作；跨批建议过滤并显式提示。所有文件操作先展示 Diff 再由用户确认。
5. 最终应用必须 confirmed: true，并复检工作区身份、源码树与数据库基线；备份、
   恢复 journal、目录交换和 SQLite 事务共同保护失败回滚及题目关联一致性。
   恢复失败保留证据，禁止自动清除。放弃只清理受管暂存目录。
6. 暂存内选中的 AI 文件计划先复制备份，任一操作失败即恢复文件、清单与条目快照；
   恢复失败保留现场。最终应用以一次 SQLite 事务同时发布索引、元数据与 applied 状态，
   原有模板 ID、用户笔记和题目关联保持稳定。
7. 中断应用只读发现于“备份与恢复”，用户勾选确认后恢复。数据库未提交时退回原树，
   已提交时核验新树并完成收尾；备份继续保留。含未完成暂存或恢复记录时阻止便携备份
   导出/恢复，避免静默遗漏源副本或覆盖暂存状态。
8. 不增加依赖或 Provider 协议。保留已有批量 IPC 以保护现有 V2 行为；真实新桌面
   批量入口进入暂存流程。正式模板库 AI 不作为导入后的自动副作用运行。

## 验证与后果

新增数据结构只通过 migration 演进；空库与既有 V2 升级均测试。服务/数据库/
Renderer 回归覆盖逐项进度、迟到响应、跨工作区、审查和最终回滚；真实 Electron
用临时工作区与本地 mock Provider 验证确认、重启、亮暗截图。暂存复制增加磁盘占用；
只有用户放弃或成功应用后清理。S3 的规范分类结果需在后续组合时再次验收。

## 分类语义边界

删除来源实现中将“背包问题”固定转为“动态规划/01背包”的路径补丁及默认移动；
目录只提供线索，不据此推断 01、完全、多重等具体类型。Main 与暂存审查仍使用当前批
可操作 ID 白名单；S3 的源码证据契约和规范分类结果由统筹阶段组合验收。

## 组合复核：跨进程工作区所有权

S5 发现不同 userData 的实例仍共享同一物理 `.awb/workspace.sqlite`，原有实例内锁与
单批 CAS 不能阻止不同批次同时交换模板目录。因此在 `activateContainer` 的创建、
升级、打开和 migration 之前，先规范化物理容器路径并获得独占所有权。

根部固定 `.awb-runtime-ownership.sqlite` 使用独立 SQLite 连接持有 `BEGIN EXCLUSIVE`，
其 application_id 只标识受管控制文件。整个工作区活跃期间持有，第二实例直接拒绝激活，
从而同时覆盖模板创建、编辑、文件计划、重扫、导入和恢复入口。SQLite 内核锁在崩溃后
由操作系统释放，不使用 PID/TTL 删除旧锁。未知格式、symlink 或无法判定的文件拒绝使用。

控制文件及其 journal/WAL/SHM 永不主动删除；放在 `.awb` 之外，避免创建失败回滚和
业务数据恢复更换锁 inode。空目录检查与普通目录升级仅排除此组已验证控制文件，
不得迁入 templates。便携备份只打包原有显式业务内容，排除此控制文件组。

切换新工作区成功并完成初始化后才关闭旧数据库与释放旧所有权；失败恢复旧数据库、
storage 和所有权一致状态。退出沿用等待 AI/后台任务完成后关闭数据库的顺序。
自动启动时发生占用冲突给出“先关闭另一个实例”的受控提示，不建议重复重启。
新 userData 打开有暂存恢复 journal 的工作区时只载入原索引，显式恢复前不自动重扫。
不改变 0009，不占用 S4 的 0010；S4 负责用户分类确认的持久化，不承担这项互斥修复。
