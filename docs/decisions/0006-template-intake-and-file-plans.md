# ADR-0006：模板入库、元数据与文件变更计划

- 状态：已接受
- 日期：2026-07-14
- 范围：阶段 5

## 背景

阶段 5 需要同时改善单个模板入库和整个工作区整理。用户模板是不可替代数据，AI 不能直接移动、覆盖或删除文件；模板路径变化还会改变当前路径派生的模板 ID，并影响题目关联。

## 决策

1. 模板入库支持粘贴源码或由系统选择器读取单个源码文件。选择器只返回文件名和经过大小/文本校验的内容，不向 Renderer 暴露绝对路径。
2. AI 分类只返回建议保存路径和结构化元数据。建议先显示在表单中，用户确认后才创建文件；目标文件存在时绝不覆盖。
3. 模板元数据保存在 SQLite 的 `template_metadata`，源码仍以用户文件为准。元数据包括标签、时空复杂度、解决的问题、适用约束、前置条件、常见错误和用户笔记。
4. 全库审计先执行确定性的只读扫描，报告重复内容、空文件、命名异常、缺少元数据和失效关联。扫描不调用 AI、不修改文件。
5. AI 只根据有限、明确展示的工作区摘要生成 `FileChangePlan`。首版可执行操作为受限移动/重命名、删除和元数据更新；不允许模型提供任意命令、绝对路径或文件内容覆盖。
6. 计划保存到 SQLite，状态为 `draft`、`cancelled` 或 `applied`。取消计划只改变计划状态，不触碰工作区文件。
7. 执行前重新校验源文件、目标路径、扩展名、目标冲突和工作区授权边界。每个被修改/删除的文件先复制到 `userData/file-plan-backups/<execution-id>/`。
8. 文件操作失败时，按逆序恢复已完成操作；随后重新扫描工作区。成功后保存执行记录和备份引用，并提供显式“撤销”入口。
9. 模板移动后，以新路径计算新 ID，并在数据库事务中迁移题目关联和模板元数据。删除模板时保留旧索引为 unavailable，使既有关联可见但不可打开。
10. 撤销前执行完整冲突预检；存在新文件占用原路径或目标文件已被外部修改时拒绝自动撤销，不覆盖用户后续改动。
11. 阶段 5 不实现 AI 自动合并或源码覆盖。高度相似内容可以作为建议展示，但涉及语义合并时必须由用户手工处理。

## 后果

- 路径派生 ID 的关系迁移逻辑必须被独立测试；长期可评估改为稳定 UUID，但本阶段不进行破坏性 schema 重写。
- 备份会占用额外磁盘空间；阶段 6 需要提供保留策略和清理说明。
- 计划执行是文件系统补偿事务，不具备跨文件系统数据库事务的原子性，因此执行日志和可操作错误是完成定义的一部分。
