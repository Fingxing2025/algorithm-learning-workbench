# ADR-0003：题目卡片、模板关联与本地图片

- 状态：已接受
- 日期：2026-07-14

## 背景

阶段 2 要让用户从真实桌面入口创建题目卡片，并在题目和模板两侧查看、添加或解除多对多关联。题目与图片是不可替代的用户数据；同时，模板索引会在目录重扫后更新，不能因为索引重建而静默删除用户已经确认的关联。

## 决定

1. `Problem` 使用 UUID，包含标题、平台、题号、链接、难度、标签、题面、备注、状态和创建/更新时间。状态首版固定为“未开始、尝试中、已解决”；难度保留为可选短文本，以兼容不同平台的等级体系。
2. 标签以经过 Zod 校验的有限字符串数组写入 JSON 字段。首版不为标签单独建表，避免在搜索与筛选需求尚未稳定时提前引入复杂关联。
3. `TemplateProblemRelation` 使用 `(problem_id, template_id)` 复合主键，关系类型为“实际使用、推荐、备选”，并记录来源“手动、AI”。阶段 2 只创建手动来源；后续 AI 草稿确认时复用同一模型。
4. 解除关联只删除关系行，绝不删除题目、模板或源码。阶段 2 不提供整张题目卡片删除，避免在备份与恢复界面完成前引入不可逆入口。
5. 模板重扫不再删除并重建全部模板行。`templates` 增加 `available` 字段：扫描前将当前工作区模板标记为不可用，随后按稳定 ID upsert 本次发现的模板并标记可用。这样暂时移动或卸载的源码不会让已确认关联消失。
6. 题目图片只允许 PNG、JPEG 和 WebP，单张最大 8 MiB，每题最多 12 张。Main 通过系统文件选择器读取图片并复制到应用数据目录 `problem-images/<problem-id>/`；SQLite 只保存受控相对路径、媒体类型、大小和原始文件名。
7. Renderer 不接收图片绝对路径。预览时通过图片 ID 请求 Main 读取受限文件并返回经过大小与类型校验的 data URL。
8. 删除图片必须由用户明确确认。Main 先将文件原子移动到应用内临时回收目录，再删除数据库记录；数据库失败时移回原位，成功后清理临时文件。遗留临时文件可安全清理，不影响正式题目记录。
9. 所有题目、关联和图片 IPC 只接收经过 Zod 校验的字段或 ID，不接受 Renderer 提供的任意文件路径。系统选择器是导入图片路径的唯一入口。
10. `0001_problems_relations` 是对阶段 1 数据库的增量 migration，不删除或重建现有工作区和模板数据。全新安装按顺序执行 `0000` 与 `0001`。

## 数据模型

- `problems`：题目卡片及用户维护的文本字段。
- `template_problem_relations`：题目和模板的多对多关联、关系类型和来源。
- `problem_images`：题目图片的受控相对路径与文件摘要。
- `templates.available`：模板当前是否能在最近一次扫描中找到。

## 后果

- 暂时缺失的模板不会显示在当前模板树，但关联记录仍保留，后续重新扫描发现同一路径时会自动恢复可用状态。
- 图片文件与 SQLite 操作需要补偿式回滚，不能假设数据库事务能够覆盖文件系统。
- 首版标签搜索在应用层完成；当数据量和筛选需求明确后，再评估规范化标签表或 SQLite FTS。
- 题目整卡删除、批量导入和 AI 推荐不属于本阶段，后续必须在明确备份与确认语义后实现。
