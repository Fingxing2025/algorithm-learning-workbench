# ADR-0032：批量导入后的语义重复分类整理

- 状态：已接受
- 日期：2026-09-01
- 范围：批量模板导入、总体文件 AI 只读审计与文件计划生成

## 背景

批量导入会对每个源码文件独立请求分类。模型可能分别创建“字符串”和“字符串算法”、
“算法”和“算法基础”等语义重复的目录分支。导入提交已有物理路径冲突预检，但无法发现
这种跨文件、跨请求的分类重复；总体文件 AI 也只会收到重复/相似源码等局部审计项，难以
形成完整的合并方案。

## 决定

1. 在 Main 的只读工作区审计中增加 `path-inconsistency` 问题类型。对真实目录链做保守
   的 Unicode NFKC、大小写、空白/标点和常见描述性后缀归一化（如“基础”“算法”“模板”、
   “路径/路”），在相同归一化父级下只把归一化后完全相同的目录节点分组；不做无界模糊匹配。
2. 每组选择模板数量更多、路径更短且字典序稳定的现有目录作为保留目录；审计项只列出
   需要迁移的非保留分支模板，并返回完整路径数量与截断标记。审计仍是只读，不移动真实文件。
3. 总体文件 AI 计划的完整目录上下文继续作为稳定前缀；`path-inconsistency` 列出的每个
   模板必须由 AI 返回一项安全 `move`。Main 校验扩展名、工作区边界、目标占用和跨批重复，
   缺少任一必需移动时整份计划拒绝，不产生半份计划。
4. 文件计划仍遵循预览、Diff、逐项选择、二次确认、备份、失败回滚和执行后复扫；AI 不获得
   直接改盘权限。批量导入自身仍保留批内物理路径冲突的逐项处理。

## 后果

- 目录树会在审计中明确展示语义重复分支，并可通过一份计划统一到真实已有目录。
- 归一化规则刻意保守，无法识别的近义词仍交由用户和 AI 审查，不自动合并；误判风险低于
  无界相似度合并。
- 新增的是审计契约枚举和内存计算，不新增数据库字段、迁移、Provider 协议或权限。
- 若重复分类组超过路径展示上限，计划在发送前拒绝并要求按顶层目录分批处理，避免静默漏项。
