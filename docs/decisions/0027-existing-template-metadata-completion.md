# ADR-0027：已有模板的单个与批量 AI 元数据补全

## 背景

模板入库已经可以在写入前生成路径和元数据，但已经存在于当前工作区的模板只能手工编辑元数据，或通过总体文件 AI 计划间接补全。用户需要从模板库直接对一份或多份既有模板补全结构化元数据。

该流程会读取用户模板源码、调用 `template-metadata` AI 任务并写入 SQLite，因此必须继续遵守发送预览、用户确认、Renderer 无系统权限和用户数据不被静默覆盖的边界。

## 决定

1. 模板库提供两个入口：算法卡片中的“AI 补全空白字段”和页面工具栏中的“批量 AI 补全”。单个补全是批量协议中只有一项的特例。
2. Main 在发送前读取当前工作区内受授权模板的源码与元数据，创建带 TTL 的内存预览快照。快照绑定工作区、Provider/模型、完整目录版本、源码内容和元数据版本；过期、跨工作区或版本变化时拒绝生成。
3. AI 只接收模板相对路径、源码、既有非笔记元数据和完整工作区目录上下文。`notes` 永不发送，也不在模型输出 Schema 中出现。
4. 模型只能为当前为空的字段提出补全值。非空字段由 Main 强制保留；Renderer 展示逐模板、逐字段 Diff，用户可取消任意字段或整份模板。
5. 确认请求只引用 Main 保存的补全草稿和所选字段。Main 再次验证工作区、源码和元数据版本，并在单个 SQLite 事务中写入全部选择；任一项变化时整批拒绝，不产生部分写入。
6. 批量补全首版每次最多 20 份模板，按确定性顺序逐份调用 Provider，并支持取消活动请求。没有可补字段的模板不调用 AI。
7. 复用现有 `template-metadata` 任务路由，不增加数据库字段、migration、Provider 协议或新依赖。

## 后果

- 用户可在不移动或改写模板文件的前提下补全已有算法卡片。
- 批量生成可能产生多次 Provider 调用；发送预览会明确模板数、源码字符数和排除内容。
- 由于写入前保存的是短期 Main 内存草稿，应用重启、预览过期或模板变化后需要重新生成；不会持久化未经确认的 AI 草稿。
