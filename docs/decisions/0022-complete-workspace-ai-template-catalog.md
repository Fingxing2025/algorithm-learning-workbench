# ADR-0022：完整分级工作区 AI 模板目录

- 状态：已接受
- 日期：2026-07-23
- 范围：新建模板的 AI 路径/元数据补全、题目图文 AI 分析

## 背景

ADR-0012 将工作区上下文拆为目录摘要与本地检索的相关模板，避免无条件上传全部源码。实现随后为目录摘要设置 80,000 字符上限，并只向题目候选校验暴露最多 24 个相关模板。这个边界能控制请求体，但会让目录中的少见模板名被省略，也会让未进入局部召回的真实模板失去题目推荐资格；纯图片题目尤其无法依赖题面文本完成可靠的本地召回。

本产品的典型个人工作区为 0～300 个模板。两个现有 AI 功能需要在一次请求中看到完整目录结构、全部稳定模板 ID 和名称，同时继续排除用户笔记、绝对路径、密钥和大规模完整源码。

## 决定

1. Main 生成 `schemaVersion: 1` 的 `WorkspaceTemplateCatalog`。目录使用确定性排序的分级树；工作区根目录中的模板单独放在 `rootTemplates`。每个目录节点包含名称、工作区相对路径、语言、模板数、子目录与直属模板；每份模板至少包含稳定 ID、名称、语言和确定性摘要。
2. 可用模板不超过 300 个时，目录中全部模板 ID、名称和所在目录都必须进入稳定上下文。不得以字符上限、相关性排序或 Provider 能力为由静默删除名称。超过 300 个可用模板时，请求在网络发送前以 `AI_CONTEXT_TOO_LARGE` 失败，并提示用户拆分工作区或减少可用模板；本版本不实现多轮分批归并。
3. `workspaceContextVersion` 使用工作区标识/名称、可用模板集合、稳定 ID、名称、相对路径、语言、修改时间、不含笔记的元数据与关联统计确定性生成。相同内容、不同查询和不同枚举顺序得到相同版本；模板路径、元数据、关联统计或可用集合变化会失效版本。稳定前缀的具体精简形态另外进入缓存键，避免同一缓存键对应不同序列化内容。
4. 摘要优先使用已有 `solves`，不发起隐藏的 AI 摘要请求；缺失时保持空字符串。摘要、标签、约束、前置条件、常见错误和复杂度有本地固定长度/数量上限，不虚构缺失能力。`notes` 永不进入 catalog 或相关模板详情。
5. 应用使用 96,000 个估算输入 Token 的安全预算，并将工作区上下文本身限制在 240,000 字符以内。预算按以下顺序退化：先把摘要从最多 320 字符缩到 120 字符，再省略标签、约束、前置条件、常见错误和复杂度等附加字段，再省略有限相关源码片段。目录结构、模板 ID、名称和语言不可退化；若保留这些必要数据后仍超限，则在发送前失败。
6. 继续使用最多 24 个本地相关模板、每份最多 2,000 字符且合计最多 30,000 字符的源码片段作为辅助详细上下文。源码不可读、含 NUL 或预算不足时只省略片段，不从完整 catalog 和候选资格映射中删除该模板。默认仍不发送全库完整源码。
7. 新建模板 Prompt 必须先全面检查 `workspaceCatalog`，优先复用语义匹配的现有目录；`relatedTemplates` 只提供详细补充，不能决定完整目录。Main 继续独立验证现有目录、父目录、分类链、文件名、扩展名和工作区路径边界；结果仍进入 Renderer 逐字段冲突审查，确认前零写入。
8. 题目分析 Prompt 必须全面比较 `workspaceCatalog`，最多返回 8 个真实模板 ID。Main 使用完整 `catalogTemplateRefs` 校验候选，确定性过滤伪造、重复、不可用或跨工作区 ID；不再用 24 个 `relatedTemplateRefs` 作为资格全集。AI 结果继续只存在 Renderer 内存草稿，确认前不创建题目、图片或关系。
9. 请求预览公开模板总数、发送名称数、摘要数、目录节点数、相关源码片段数/字符数、目录上下文估算 Token、三类可接受退化以及模板名称是否被裁剪。模板名称裁剪在当前实现中始终为 `false`；无法保证时请求不会生成预览。
10. 完整 catalog 作为现有 Prompt Cache 稳定前缀进入五类 Provider Adapter。Chat Completions、Responses、Anthropic Messages、Gemini GenerateContent 和 Ollama 继续使用相同统一请求语义、原生结构化输出有限降级和本地 Zod 后置校验；本决定不增加第二次精排调用，不改变 timeout、重试、1 MiB 响应上限或取消协议。

## 明确不发送

- 工作区绝对路径、数据库路径、图片绝对路径、备份路径和历史文件计划。
- API Key、密钥引用、加密密文、自定义鉴权头和错误日志。
- 模板 `notes`、题目以外的无关用户数据和全库完整源码。

## 后果

- 0～300 个模板的目录与名称完整可见，少见模板不再因本地 24 项召回而失去推荐资格；请求体会比旧目录摘要更大。
- 极长名称/路径、接近上限的题面或大量图片可能触发附加字段/源码退化，极端情况下会在网络发送前明确失败。估算 Token 不是供应商模型窗口的官方保证；具体 Provider 仍可能返回上下文上限错误。
- 本决定不改变 SQLite schema、模板稳定 ID、题目/模板关系、图片、备份恢复或文件计划格式，因此不需要 migration；全新与已有 V2 userData 使用同一运行时生成逻辑。
- 未来若支持超过 300 个模板，应新增多轮分批全库处理与可审查归并协议，不能恢复静默截断或仅局部候选资格。
