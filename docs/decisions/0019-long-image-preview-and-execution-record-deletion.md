# ADR-0019：长题目图片预览与执行记录安全删除

- 状态：已接受
- 日期：2026-07-18

## 背景

题目图片遮罩当前使用 `max-height: 100%` 与 `object-contain`。普通截图可以完整查看，但纵横比很大的长图会被整体压缩到窗口高度，文字无法阅读；遮罩也没有可聚焦的独立滚动区域。

总体文件 AI 管理已经允许把非草稿计划软归档，但“执行与撤销”记录没有删除入口。数据管理页的“执行记录”统计直接来自 `file_change_executions`。仍为 `applied` 的执行记录对应可恢复用户文件的备份，不能为了清理列表静默丢失撤销能力。

## 决定

1. 题目图片预览默认使用“按宽度查看”：图片按预览区域可用宽度显示，长图在遮罩内部纵向滚动，滚动区域可聚焦并支持浏览器标准键盘滚动。
2. 预览提供“按宽度查看”和“适合窗口”两个互斥模式；适合窗口继续完整缩放整张图片。每次打开预览都回到按宽度模式和图片顶部。
3. 图片预览、文件名和控制按钮仍只使用 Renderer 已取得的受控 `data:` URL，不新增文件系统、路径或权限接口。
4. 新增命名明确、Zod 校验的 `delete-file-executions` IPC。Renderer 只提交不重复的执行记录 UUID，不提交数据库条件、备份路径或文件路径。
5. 只有状态为 `rolled-back`、属于当前活动工作区的执行记录可以删除。仍为 `applied` 的记录必须先完成现有安全撤销；应用不提供绕过撤销备份保护的永久删除。
6. 单条和批量删除都必须先展示确认。确认文案说明：只删除已撤销执行记录；模板、题目、关系和源码不变；对应撤销/重新草拟入口将不再可用；数据管理统计会同步减少。
7. Repository 在单一 SQLite 事务中验证全部 ID 与状态后再批量删除；任一 ID 不存在、属于其他工作区、仍可撤销或状态变化时整批拒绝，不删除任何记录。
8. 撤销流程已经移除对应 `file-plan-backups/<execution-id>`，因此删除已撤销记录不再执行文件系统删除，不产生新的备份、回滚目录或恢复 journal。
9. 数据管理页继续统计数据库中的真实执行记录数，不增加缓存或重复状态。删除成功后重新进入或重新诊断数据管理页即可得到同步计数。
10. 本变更不新增数据库字段或 migration；`file_change_executions` 现有外键与状态字段足以表达边界。

## 后果

- 长图可以在可读尺寸下从顶部滚动到底部，也可切回整图概览。
- 用户可以清理已经完成撤销的执行历史，数据管理计数与数据库事实保持一致。
- 已执行且仍有撤销价值的记录不会出现删除入口；这是保护用户文件而不是 UI 限制。
- 删除执行记录后，依赖该 `rolled-back` 记录判断的“复制为新计划”能力也会消失；确认前必须明确提示。
- 计划记录软归档语义不变；删除计划记录仍不影响执行记录和撤销备份。
