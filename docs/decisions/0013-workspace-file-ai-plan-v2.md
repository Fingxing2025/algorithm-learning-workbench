# 0013：工作区文件 AI 计划 V2

## 背景

旧文件计划任务按路径只取前 250 个模板，没有发送预览、输出语言、缓存上下文、证据/风险和执行前文件版本校验。其 JSON 修复也与模板补全、题目分析不一致。

## 决定

1. 本地确定性审计仍是事实来源。完全重复文件由本地生成建议；高度相似文件只提供给 AI 和用户审查，默认不选中删除。
2. 计划输入使用全库分类摘要、审计涉及的模板和本地相关性检索，不再按路径截取前 250 项。源码仍使用字符上限。
3. 用户笔记允许发送，但发送预览必须单独显示数量。AI 只能把笔记错误作为可选元数据修正建议，默认不选中，不得静默改写。
4. 请求前展示 Provider、模型、语言、审计范围、候选模板、源码片段、用户笔记、截断状态、Token 粗估和缓存键。确认前不发起网络请求。
5. 复用版本化 `WorkspaceAiContext`、Provider Prompt Cache、统一结构化输出、一次受限修复和原生 Schema 兼容降级。
6. 计划支持中英文。路径和元数据的语言规则与模板补全一致，复杂度、源码语言和惯用算法专名保持原样。
7. 每项操作保存建议来源、证据、置信度、风险、适用条件、备选方案和默认选中状态。同一模板在一份计划中仍最多一项操作。
8. 新计划记录源文件 SHA-256、大小、修改时间、元数据版本和移动目标状态。执行前重新校验；不一致时拒绝整批执行并要求重新生成。
9. 生成请求可取消；429 尊重有上限的 `Retry-After`。诊断导出只包含任务阶段、模型、数量、上下文版本和错误类型，不包含 API Key、源码、笔记、题面或文件路径。
10. 移动、删除和元数据修改仍需用户勾选、二次确认、执行前备份和失败回滚；AI 永远不直接修改工作区。

## 后果

- `operations_json` 改为版本化 envelope，读取时仍兼容旧版数组格式，不需要删库或改变 SQLite 表结构。
- 候选选取是“审计问题相关 + 本地检索相关”，仍保留明确上限和截断提示。
- 旧计划没有前置条件时可继续按旧逻辑审查；复制为新计划时会生成新前置条件。
