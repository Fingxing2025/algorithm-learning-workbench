# ADR-0020：增量模板索引、可取消后台任务与键集分页

- 状态：已接受
- 日期：2026-07-19
- 范围：Session E

## 背景

0.1.2 的工作区重扫每次都遍历全部文件、把当前工作区全部模板标记为不可用，再逐批 upsert 全量结果。无变化重扫与完整重扫的工作量几乎相同。模板审计会重新读取源码，最多只检查前 2,000 个模板，并让前 500 份源码参与两两相似度比较；题目列表把全部题目、图片和关系载入后，对每道题重复扫描全部图片与关系；AI 上下文逐模板查询元数据并全量评分。

现有异步 IPC 返回 Promise，但扫描、审计的完整结果仍由一个长调用控制，用户看不到确定阶段，不能取消工作区扫描或本地源码审计。扩大 500/2,000/250 等安全阀只会隐藏复杂度和无提示截断，不能证明 1k/5k/10k 工作区可用。

模板源码、元数据和题目关系是不可替代的用户数据。任何增量结果、移动识别或取消都不能发布半完成索引、错误迁移稳定 ID、修改源码或破坏现有备份/撤销语义。Renderer 也不能因此获得文件系统、SQLite、原始 IPC 或路径权限。

## 决定

### 1. SQLite 中的版本化增量索引

1. 新增顺序 migration `0006_performance_indexing`，在 `templates` 保存：原始内容 SHA-256、受控文件身份、变化令牌、规范化源码 SHA-256、受限相似度签名和索引版本。`workspaces` 保存最近一次扫描的聚合工作量 JSON。所有字段由 Main 生成，Renderer 不提交。
2. 首版 `template_index_version = 1`。索引版本缺失、不匹配、字段损坏或迁移后的旧记录会在下一次扫描按普通文件重新读取并重建；不能解析的签名只使单条索引失效，不删除数据库或跳过路径校验。
3. 变化令牌由文件大小、mtime 与 ctime/平台文件状态组成，只用于决定能否安全复用既有内容哈希。mtime 不是唯一判断依据；大小相同且 mtime 被恢复的内容写入仍会改变 ctime 并触发重新哈希。任何需要更新或无法证明未变化的文件都读取完整内容并计算 SHA-256。
4. 读取前后重新检查文件状态。文件在扫描中途变化、变成符号链接、越过授权根目录或无法稳定读取时，整次索引发布失败并给出安全错误；旧 SQLite 索引继续可用，不把不稳定文件发布为新事实。
5. 扫描先在内存中形成完整候选结果，最后由单一 SQLite 事务发布模板增量与工作区摘要。取消、异常中断或事务失败不会把全部模板先标记不可用，也不会留下部分新索引。
6. Repository 只插入新增项、更新真实变化/移动项、把确实删除的旧项标记不可用，并保持未变化行不写。扫描结果继续按受控相对路径稳定排序；强制完整重建与增量扫描必须产生相同的公开模板列表、哈希和审计分组。

### 2. 稳定 ID 与移动识别

1. 新模板仍使用现有 64 位十六进制 ID 契约。索引一旦建立，后续路径变化不主动重算 ID。
2. 应用内确认的移动继续以 ADR-0017 的显式预览、备份、指纹校验和稳定 ID 覆盖为最高优先级。
3. 应用外移动首先只在同一工作区本次“旧路径消失 + 新路径出现”集合内匹配受控文件身份；若文件身份不可用，只有内容 SHA-256 和大小组合在双方都唯一时才允许匹配。重复源码、多个候选或冲突路径不猜测身份：新路径获得其确定性新 ID，旧记录保留为不可用。
4. 稳定 ID 匹配只迁移索引路径，不移动用户文件、不创建备份，也不改变元数据和题目关系；因此真实重命名可保持关系，复制文件不会错误继承原模板身份。

### 3. 审计索引与复杂度

1. 首次/真实变化扫描同步生成规范化内容哈希和受限相似度签名；无变化审计复用 SQLite 索引，不重复读取全部源码。
2. 完全重复分组使用规范化 SHA-256。高相似候选先按扩展名、长度桶和签名 band 建立有限候选集，再对候选计算精确 Jaccard，避免全库 N×M 两两比较。
3. 仍保留单条签名大小、每组展示路径和公开问题数量上限；任何安全上限都在结果中返回已处理数量、总量/未知状态、截断原因和用户下一步，不能静默描述为完整审计。
4. 文件计划发送给 Provider 的源码字符和候选隐私上限保持不变。Session E 优化本地召回和可理解截断，不扩大 Provider 内容边界。

### 4. 进程内后台任务

1. 新增 Main `BackgroundTaskRegistry`，首批任务为工作区扫描和本地源码审计。任务状态只保存在进程内，包含不透明 UUID、任务类型、阶段、已处理数、总数或未知、开始/结束时间、安全错误和最终领域结果；不写 SQLite，不跨应用重启恢复。
2. Preload 只暴露按领域命名的启动操作，以及统一的任务状态查询和取消操作。所有请求/响应经过 Zod；不暴露 `ipcRenderer`、`AbortController`、回调通道、绝对路径或原始错误。
3. 同一工作区、同一类型最多一个活动任务。重复启动明确复用或拒绝；首版选择返回既有活动任务状态，不并发扫描或审计同一工作区。
4. Renderer 通过有上限的短轮询读取聚合进度。扫描阶段至少区分发现、哈希/索引和发布；审计至少区分索引检查、重复分组、相似候选和结果整理。无法预先知道总数时返回 `totalCount = null`，不伪造百分比。
5. 取消先使 Renderer 立即退出忙碌状态，再由 Main 的 `AbortController` 阻止后续 I/O、相似度批次和最终 SQLite 发布。CPU 循环按受控批次让出事件循环，确保取消/状态查询可被处理。
6. 应用退出时取消全部活动任务。任务完成、失败或取消后只保留有限数量的安全摘要，防止进程内记录无限增长；结果不含源码、题面、Provider 正文、API Key 或绝对路径。

### 5. 键集分页与直接详情查询

1. 题目列表新增以 `(updated_at DESC, id DESC)` 为稳定顺序的键集游标；游标由 Main 解码并校验，Renderer 不能提交 SQL、OFFSET 或任意排序字段。单题详情按 UUID 直接查询自身图片和关系，不再重建全题目列表。
2. 模板和历史列表新增稳定键集查询边界；模板使用 `(relative_path ASC, id ASC)`，历史使用 `(created_at DESC, id DESC)`。SQLite migration 增加与条件/排序一致的复合索引。
3. 现有兼容 API 可在过渡期保留，但真实 Renderer 入口改用分页接口。页面显示已加载数量、总数量、是否还有下一页以及加载失败的下一步；不能把“只加载首批”描述成全部数据。
4. 模板树继续使用虚拟滚动和既有键盘契约。分页加载不会改变已加载行的稳定 ID；搜索定位通过 Main 的受控搜索/定位查询找到目标页或最小必要路径，不要求 Renderer 一次载入完整模板领域对象。
5. 安全上限继续存在时，公开结果必须包含 `processedCount`、`totalCount` 或未知、`truncatedReason` 和 `nextAction`。不通过隐藏详情、删除主操作或提高常量制造性能提升。

## migration、恢复与失效策略

- `0006_performance_indexing` 只增加可空索引字段、工作区扫描统计和复合 SQLite 索引；旧 V2 数据原位升级。旧行在下一次扫描惰性补全，应用不要求删除数据库。
- `.awb-backup` `v1` 继续备份完整 SQLite 快照，因此自然包含新字段和索引；恢复旧快照后 migration 重新执行，缺失/旧版本索引按规则重建。备份清单格式不变。
- SQLite schema migration 事务失败时不会记录 migration ID。扫描索引发布事务失败、进程退出或取消时保留上一个完整索引；没有独立临时索引文件或半完成 marker 需要清理。
- 全新 userData 从 migration 0000 顺序升级到 0006；已有 V2 userData 原位增加字段/索引；旧项目仍不读取、不迁移。

## 后果

- 首次扫描会为每份受支持源码读取并计算内容/相似度索引，可能比旧版只 stat 的首次扫描更重；收益体现在确定性变化识别、无变化重扫、重复审计和后续本地检索。
- ctime 是快速复用所需的变化证据，不是内容真实性本身；一旦变化令牌不一致仍以完整 SHA-256 为准。强制完整重建可用于失效恢复和一致性测试。
- 应用外移动的唯一性规则宁可放弃迁移，也不把元数据和题目关系错误附着到重复源码。
- 进程内协作式任务不会在崩溃或重启后继续；首版明确要求旧索引保持完整、用户重新启动任务，不引入持久化作业队列或新的后台进程权限。
- 键集分页不支持任意跳到“第 N 页”，但在大数据量下不会像 OFFSET 一样随页码线性退化；全局搜索/定位提供直接入口。
- Renderer 的 Node、文件系统、SQLite、密钥和原始 IPC 权限不变；Session A/B/C/D 的备份、AI、发布与可访问性契约继续作为回归门禁。
