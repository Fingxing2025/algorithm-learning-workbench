# 0008：工作区滚动、代码主题与 AI 计划恢复

## 背景

模板库和题目工作区的内部列表声明了滚动，但页面根节点没有占满主内容区，导致窗口高度变化后滚动容器无法获得受约束高度。源码仍以纯文本展示；文件 AI 计划只接受一种严格 JSON 外形；Provider 配置又与 AI 操作共用一个页签工作区，用户难以判断“设置”和“执行”的边界。

## 决定

- 模板库、题目工作区、算法详情和主内容动画容器显式占满可用高度，列表与详情各自拥有滚动区域。
- Renderer 使用 `highlight.js` 的按语言注册入口渲染只读语法高亮。代码主题独立于应用主题，可选择跟随应用、VS Code Light+、VS Code Dark+ 和 Monokai，并仅在本机 `localStorage` 保存主题偏好。
- AI 管理只承载会产生草稿或计划的工作流；AI 设置只承载 Provider、密钥、模型能力和任务路由。两个入口不再共享内部页签。
- 文件计划响应先提取完整 JSON，兼容代码围栏、前后说明、直接数组和常见包装对象。模型元数据允许返回部分字段，由本地与现有元数据安全合并。
- 首次解析或 schema 校验失败时，只将受限长度的原始模型响应交给同一任务路由做一次格式修复，不重新发送工作区源码。第二次仍失败则返回可操作错误；任何失败都不创建计划、不修改文件。
- 宽松解析只负责恢复外形，所有操作仍必须引用当前工作区模板，并继续经过路径、扩展名、重复删除资格和最终 Zod schema 校验。

## 后果

- 代码高亮增加一个纯 JavaScript 依赖，但不增加原生模块或新的进程权限。
- 不可靠模型有一次自动恢复机会，可能额外产生一次请求；界面必须明确失败不影响文件。
- 旧的“AI 管理 → Provider 配置”测试路径改为直接进入“AI 设置”。
