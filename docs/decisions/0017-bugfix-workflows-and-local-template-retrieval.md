# ADR-0017：工作区状态、模板移动、计划归档与统一题目草稿

- 状态：已接受
- 日期：2026-07-17
- 范围：Bugfix Session

## 背景

当前模板树在每次挂载时默认展开一级目录，数据管理统计全部历史模板索引，模板移动会按新路径重算 ID，文件计划没有安全删除入口，手动新建题目与 AI 分析又维护两套互不共享的草稿。上述行为会造成界面状态丢失、统计口径不一致、已确认关系迁移复杂、历史列表无限增长，以及 AI 失败时用户手工输入无法继续使用。

本次修复还要求题目分析从当前工作区检索多个不同方向的本地模板。模板源码、题面、图片和文件计划备份均是受保护数据；Renderer 不能因交互合并获得文件系统、数据库或任意 IPC 能力。

## 决定

1. 模板树的“手动展开状态”作为 Renderer 展示偏好保存在 `localStorage`，键由工作区 UUID 组成，值只包含规范化的相对目录行 ID。新工作区默认空集合，即所有目录折叠。加载与重扫时只保留当前树仍存在的目录；不同工作区互不复用。
2. 搜索结果定位和当前选中模板所需的展开使用独立的内存临时集合，不写入持久化偏好。离开模板库或结束定位后，常规树仍使用用户最后一次手动展开状态。
3. 用户手动重命名或移动模板时，Renderer 只提交模板 ID 和新的工作区内相对路径进行预览；Main 校验扩展名、目录穿越、绝对路径、符号链接、大小写冲突、文件/目录占用和源文件指纹，并返回不透明预览 ID。确认执行只提交该预览 ID。
4. 模板移动复用文件计划的备份、执行记录和撤销资产，但移动后的模板继续使用原稳定模板 ID。扫描服务允许 Main 为本次已确认移动向目标相对路径提供一次受控 ID 覆盖；普通外部扫描仍按既有路径摘要发现新文件。这样元数据和题目关系不需要删除重建，撤销时同一 ID 回到原路径。
5. 移动执行前把源码复制到 `userData/file-plan-backups/<execution-id>/`。目标目录创建、真实文件 `rename`、SQLite 索引更新、执行记录和工作区重扫按补偿事务处理；任何一步失败都把文件和索引恢复到原状态。目标永不静默覆盖，确认后源指纹变化时整次操作拒绝。
6. 文件计划“删除记录”采用软归档，不物理删除计划、执行记录或备份。`file_change_plans` 新增可空 `archived_at` 字段，并通过增量 migration 升级。普通列表只读取未归档计划；`draft` 计划不可归档，`cancelled` 与已执行计划可归档，已执行计划的撤销能力和备份保持不变。
7. 单条和批量归档只接受 Zod 校验的不透明 UUID 数组。Main 在单个 SQLite 事务中重新检查工作区、归档状态和计划状态；任一 ID 伪造、已变化或仍为草稿时拒绝整批操作。Renderer 的确认层显示数量和状态，但不提交 SQL、路径或任意筛选条件。
8. 手动新建与 AI 分析合并为一份内存题目草稿。草稿从一开始就包含题目字段、图片和多模板关系；用户可纯手工确认，也可随时请求 AI 补全。AI 失败、取消或迟到响应不重置现有字段，且同一 `requestId` 仍由 Main 运行注册表拒绝重复提交。
9. 无论是否使用 AI，最终创建都复用题目分析提交契约，由 Main 原子写入题目、图片和全部已确认关系。关闭或取消统一窗口不调用提交接口，不创建题目目录、数据库行或关系。编辑既有题目继续使用独立编辑器，不改变现有更新语义。
10. 统一题目草稿允许手动搜索并选择多个当前工作区模板。AI 候选仍是可取消、可改关系类型与备注的草稿；高置信度建议可默认选中，低置信度建议仅展示。关系持久化枚举继续使用 `used/recommended/alternative`，不扩展数据库关系类型。
11. AI 候选增加仅存在于草稿契约中的作用分类：直接解法、子问题、前置能力、优化方向或替代解法。该分类用于解释推荐，不进入数据库关系枚举；用户确认后的说明保存在既有关系备注中。
12. 本地候选检索只读取当前活动工作区中 `available = true` 且能再次通过授权根目录与普通文件校验的模板。排序综合名称、相对路径、标签、时空复杂度、用途、约束、前置条件、关联统计和受限源码片段，并使用中英文词元与中文短 n-gram。候选池最多 24 份、源码片段总计最多 30,000 字符，最终草稿最多 8 份。
13. 本地检索不会固定 Top 1。文本输入优先选取有证据的高分模板，并在上限内保留不同顶层目录的补充候选；纯图片输入可使用按目录分散的受控候选池交由视觉模型判断。Main 只接受本次候选池中的真实模板 ID，确定性去重；不存在、不可用、越界、符号链接或读取失败的模板一律拒绝。
14. 发送给 Provider 的工作区上下文不包含绝对路径、用户笔记、API Key 或完整模板库源码。日志只记录任务、数量、上下文版本、候选 ID 摘要和错误码，不记录题面、源码正文或模型原始响应。
15. 数据管理中的普通“模板”计数改为当前活动工作区 `available = true` 的模板数量，与模板库列表使用同一口径。历史不可用索引和其他工作区记录不再混入该标签，也不通过删除数据库记录来校准数字。
16. 应用图标继续复用现有立方体节点标志和项目蓝紫青品牌渐变。打包 PNG 必须保留透明角、移除烘焙白色画布，并从同一几何源生成；macOS 安全边距在透明画布内表达，不使用额外白底。

## 数据兼容

- 新增 migration `0005_bugfix_workflows`，只为 `file_change_plans` 添加 `archived_at`，既有计划默认未归档。
- 模板、元数据、题目、图片和关系表不新增字段；已有路径派生模板 ID 保持原值，只有应用内确认的后续移动不再更换 ID。
- 备份格式仍为 `.awb-backup` `v1`。SQLite 快照自然包含新字段；旧 V2 数据原位 migration 后继续读取，不要求删除数据库。
- 模板树展开偏好只影响本机展示，不进入备份，不修改工作区文件。

## 后果

- 软归档不会立即释放 SQLite 空间，但不会破坏审计、撤销和备份保护；永久清理仍不在本次范围。
- 稳定 ID 覆盖只对已确认、已校验的应用内移动生效。用户在应用外移动文件仍会被扫描器视为旧索引不可用和新路径文件，避免基于内容猜测身份。
- 统一题目窗口代码量增加，但只保留一个创建入口和一份草稿，减少重复状态与半成品写入风险。
- 24/30,000/8 的候选限制继续是隐私与响应性安全阀；扩大上限必须更新本 ADR，而不能仅修改常量。
