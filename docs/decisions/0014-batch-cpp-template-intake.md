# 0014：批量 C++ 模板入库

## 背景

现有模板入库一次只能读取一份源码。用户需要选择多个 `.cpp` 文件，或从一个外部文件夹递归扫描 `.cpp` 文件，批量请求 AI 生成路径与元数据，再把新副本加入当前模板工作区。外部源文件不可被移动、重命名或改写。

## 决定

1. Main 进程负责多文件选择和目录扫描；Renderer 只接收经过大小、扩展名、普通文件、符号链接和文本校验的源码草稿，不获得任意文件系统权限。
2. 首版只接受 `.cpp`，单文件仍限制为 2 MiB，单批最多 100 份。目录扫描递归进行，跳过符号链接，不跟随到授权目录之外。
3. 批量来源默认全选，用户可以逐份取消或恢复选择；AI 请求和最终写入都只处理当前选中项。批量 AI 请求先展示统一发送预览，Renderer 逐份调用现有模板分类任务，以显示确定的进度并复用工作区上下文与 Prompt Cache。
4. AI 元数据不是导入前置条件。未运行 AI、AI 只完成部分项目或用户停止后，仍可使用来源文件的相对展示路径作为默认目标路径，并以空元数据导入所选项目；用户可以在写入前编辑每一项的最终路径。
5. Main 提供只读冲突预检，Renderer 在写入前展示逐项选择。已有普通文件可选择跳过、修改文件名或明确覆盖；目录、符号链接和仅大小写不同的跨平台冲突只能跳过或改名。批内重复路径也必须在提交前处理。
6. 批量提交由 Main 再次验证全部目标路径、批内冲突、源码、冲突动作和预检时生成的已有文件状态令牌，避免预检后的外部文件变化。新文件使用独占创建；覆盖项先在应用数据目录建立批次备份，再写入目标。统一重扫和元数据事务任一步失败时，恢复全部覆盖文件、删除本批新文件、移除新目录并重新扫描。
7. 成功结果只包含实际写入项目；跳过项不会发送到写入接口，也不计入导入数量。成功覆盖的备份保留在应用数据目录并带有不含源码正文的批次清单，以便后续诊断和恢复能力扩展。
8. 外部源文件只在选择或扫描时读取，提交时使用内存中的受控源码创建新副本；不对原始文件执行写入、移动或删除。
9. 批量入库不增加数据库表；继续使用现有模板与元数据结构。没有 AI 元数据时不创建元数据行；覆盖时没有新元数据则保留原有元数据。

## 后果

- 大批量 AI 补全可能耗时，界面必须显示当前进度并允许在尚未提交前取消。
- 100 份上限是桌面响应和 Provider 成本的安全阀；更大规模需要后台任务、恢复点与成本预算后再扩展。
- 批量提交可以保护工作区不留下半成品，但 AI 请求本身不是事务；失败时已产生的 Provider 用量无法撤销。
- 冲突预检只是交互提示，不能代替提交时的权限、类型与占用复检。
- 批量覆盖备份目前作为受控恢复资产保留；后续应把备份保留周期和用户可见撤销入口纳入统一文件执行记录。
