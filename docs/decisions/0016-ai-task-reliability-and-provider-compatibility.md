# ADR-0016：AI 任务稳定性、取消与五协议兼容契约

- 状态：已接受
- 日期：2026-07-17
- 范围：Session B

## 背景

题目 AI 分析、模板元数据补全和工作区文件计划已经统一使用 Provider Adapter 与结构化任务入口，但网络读取、取消和错误诊断仍存在不一致：响应头到达后缺少响应体超时，无 `Content-Length` 时会先完整缓冲响应，流式响应没有强制完成标记，只有文件计划能传播取消，且不同 HTTP 状态的重试边界不够精确。三类任务处理的是题面、图片、模板源码和用户笔记，任何稳定性诊断都不能以泄露正文为代价。

## 决定

1. 三类结构化任务统一经过 `runStructuredAiTask`。固定阶段为：Provider 请求、响应读取、Provider envelope、JSON 提取、envelope 归一化、Zod Schema 校验、一次结构修复和可选的一次业务语义重试。任务服务不得自行解析模型 JSON。
2. Provider 原始 HTTP 响应体硬上限为 1 MiB。读取使用增量字节计数；即使缺少或伪造 `Content-Length`，超过上限也立即中止并返回 `AI_RESPONSE_TOO_LARGE`。结构修复只接收前 32,000 个字符，且不会把原始响应写入数据库、日志或诊断。
3. JSON 恢复只接受完整 Markdown JSON 围栏、完整平衡对象或数组；常见、无歧义 envelope 在任务专属归一化器中展开，最后必须通过原有 Zod Schema。截断 JSON、额外危险字段或语义不合法结果不得落库、创建题目、创建可执行文件计划或修改工作区。
4. 网络阶段区分连接等待和响应读取。连接计时覆盖发送请求到收到响应头；响应计时覆盖响应体读取。两者使用同一 Provider 配置上限，但分别返回 `AI_CONNECTION_TIMEOUT` 与 `AI_RESPONSE_TIMEOUT`。用户取消返回 `AI_CANCELLED`；已开始的流式响应缺少协议完成标记、读取异常或提前关闭返回 `AI_STREAM_INTERRUPTED`。
5. Main 维护进程内、不持久化的任务运行注册表，以 `(任务类型, requestId)` 标识正在运行的题目分析、模板补全和文件计划。重复提交同一运行 ID 被拒绝。Renderer 只能通过命名明确、Zod 校验的 Preload API 取消对应任务；取消传播到所有准备阶段、退避等待和 Provider `fetch`。任务完成或失败后必须注销。
6. 任务在返回结果或写入任何状态前再次检查取消信号。文件计划在 SQLite 创建草稿前执行最后检查；已取消请求的迟到响应不得创建计划或覆盖 Renderer 状态。题目分析和模板补全仍只返回内存草稿，本 Session 不增加 AI 结果持久化。
7. 单次 Provider 阶段最多进行 3 次网络尝试，即首次加 2 次重试。只自动重试限流、连接前网络瞬断、连接超时，以及 HTTP 408、500、502、503、504。响应超时、流式中断不自动重试，避免重复产生不可判断的供应商任务和费用。401/403、模型不存在、能力不足、普通 400/422、JSON/Schema/业务语义错误不得自动重试。
8. `Retry-After` 同时兼容秒数和 HTTP 日期，并限制在 10 秒以内；无有效值时采用 250 ms、500 ms 的有上限退避。退避必须可取消。供应商给出的更长等待只用于向用户说明，不得让桌面任务无限等待。
9. HTTP 404 以及供应商明确的模型不存在错误归为 `AI_MODEL_NOT_FOUND`；401/403 为 `AI_AUTH_FAILED`；429 为 `AI_RATE_LIMITED`；不支持视觉为 `AI_CAPABILITY_UNSUPPORTED`；可重试 5xx 为 `AI_SERVICE_UNAVAILABLE`；请求参数或协议不兼容为 `AI_INVALID_RESPONSE`。公开错误附带不含正文的阶段标识，Renderer 据错误类型提供鉴权、模型、限流、网络、超时、取消、能力或输出格式的下一步。
10. OpenAI Responses 流式读取必须观察明确完成事件；错误事件、缺少完成事件、畸形数据帧或读流异常都不得作为成功。其他四类协议默认使用非流式 JSON；若兼容服务返回 SSE，也必须满足相同完成要求。
11. 结构化能力声明为 `false` 时，任务继续使用“Schema 写入 Prompt + 本地严格校验”，不发送供应商原生结构化参数。声明为 `true` 但端点以明确参数错误拒绝时，只允许一次 Schema 降级；最终本地 Zod 校验不可降级。视觉任务在请求前阻止不支持视觉的 Provider。
12. 安全诊断只允许任务类型、协议、模型标识、阶段、尝试次数、耗时、响应字节数、上下文版本、截断标记和错误代码。日志、错误、诊断、测试输出和截图不得包含 API Key、请求头、题面、模板源码、用户笔记、完整响应、思考内容或不必要的绝对路径。供应商错误正文只用于内部分类；公开错误使用本地固定文案，不回显正文。
13. 五协议契约矩阵至少覆盖成功文本、结构化 JSON、401/403、模型不存在、429/`Retry-After`、可重试 5xx、连接超时、响应超时、用户取消、无效 JSON、超大响应、截断/流式中断，以及视觉或原生结构化能力不足。矩阵测试使用合成占位数据和假密钥，不包含真实用户正文。
14. 本 Session 不修改 SQLite Schema，不改变文件计划 `operations_json` 的安全 Schema，不增加横向 AI 功能，也不改变 Session A 的备份、恢复和数据生命周期格式。

## 后果

- 三类任务共享同一解析和错误阶段，但仍保留各自严格的业务 Schema 与本地后置校验。
- 取消只对当前进程中的运行任务有效；应用重启后没有可恢复的远端生成任务，且不会自动提交迟到结果。
- 响应超时或流式中断可能已在供应商侧产生用量，因此不自动重试，并向用户建议检查模型状态后手动重试。
- 1 MiB 响应上限与 10 秒最大退避是桌面稳定性安全阀；提高上限必须更新本 ADR 与兼容矩阵，不得只改常量。
- 不新增 migration；全新安装、已有 V2 数据和 Session A 备份格式保持兼容。
