# 0010：安全删除、分层分类与计划重新草拟

## 背景

题目与模板都需要从真实桌面入口删除；模板元数据补全需要稳定遵循用户选择的输出语言，并先形成多级分类再确定路径；文件管理需要识别相同或相似模板，并允许用户在取消或回滚后重新使用计划。

这些操作跨越 Renderer、IPC、SQLite、用户授权工作区和应用数据目录，不能只在界面隐藏记录或直接删除文件。

## 决定

1. 题目删除采用补偿式流程：Main 进程先将该题目的图片目录移动到应用内临时隔离区，再在一个 SQLite 事务中删除图片、模板关系和题目。数据库失败时恢复图片目录；数据库成功后清理隔离目录。
2. 模板删除复用文件计划执行器：用户在模板卡片二次确认后创建一个只包含该模板删除操作的本地计划，执行前生成应用内备份，并保留现有撤销能力。删除后模板关系暂时作为不可用关系保留，撤销后可自动恢复；不会删除题目。
3. AI 模板分类返回 `一级领域 -> 二级算法族 -> 三级具体算法 -> 可选变体` 的结构化分类链和独立文件名。Main 进程校验每个分类段并在本地生成相对路径，不信任模型直接提供的路径。
4. 输出语言约束覆盖分类目录、标签和自然语言元数据。英文模式拒绝包含中日韩文字的结果；中文模式要求分类主层级及非空说明字段包含中文。源码语言、扩展名和复杂度表达不翻译。
5. 工作区审计区分规范化后完全相同和高相似源码。每组建议明确一个保留项，其他项只生成待确认删除建议，AI 和确定性审计都不能直接执行删除。
6. 已取消计划与已经回滚的执行计划可以“复制为新计划”。服务创建新计划 ID 和新操作 ID，并重新验证源文件、目标冲突、模板 ID 和当前重复审计；旧记录保持只读，不会被复活。

## 后果

- 题目图片与数据库记录不会因部分失败而失配。
- 模板删除需要额外备份空间，但可以从“执行与撤销”恢复。
- 分类模型输出契约发生变化；不符合语言或分层结构的响应会被明确拒绝。
- 相似度检测是建议系统，不作为自动删除依据；用户仍需逐项确认。
- 重新草拟可能因文件已变化而只保留部分仍然有效的操作，或拒绝创建空计划。
