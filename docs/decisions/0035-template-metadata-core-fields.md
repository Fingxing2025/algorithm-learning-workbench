# ADR 0035：模板元数据核心字段收敛

## 状态

已采纳（2026-09-01）。

## 决策

模板公开元数据只保留 `solves`、`timeComplexity`、`spaceComplexity`、`tags` 和用户私有的 `notes`。
`constraints`（适用约束）、`prerequisites`（前置条件）和 `commonMistakes`（常见错误）从产品契约中删除；不新增独立的 `inputOutputFormat` 字段。

`solves` 继续是字符串，编辑器使用固定三段格式：

```text
解决的问题：说明模板解决的子问题和算法模型。
输入：说明输入内容、数据结构、参数和形式。
输出：说明输出内容、返回值或调用结果的形式。
```

旧文本保持原样；源码无法确定输入或输出时标记“未从源码确定”，不得臆造。

## 兼容与回滚

数据库中的 `constraints_text`、`prerequisites`、`common_mistakes` 列保留为 deprecated 物理存储，0008 migration 只记录契约版本，不删除列、不重建表。Main 的 legacy parser 在读取旧文件计划和备份时丢弃这三个字段后再通过新的公开 Schema；它们不会进入 Renderer、搜索、AI 新输出或导出。新写入只更新核心字段，因此旧列原始值可用于未来回滚。

旧文件计划的元数据快照可安全读取和执行；回滚恢复核心字段并保留数据库中的旧列。若未来需要物理删除，必须另行升级备份协议并先验证所有恢复路径。

## AI 边界

模板元数据 AI 只返回 `solves`、复杂度和 `tags`，仅补全空字段，绝不生成或覆盖 `notes`。`solves` 尽量包含“解决的问题 / 输入 / 输出”三段；缺少源码证据时明确未知。用户已有内容原样保留，确认前始终是草稿。

## 导出范围

G1 导出只消费核心字段（复杂度、`solves`、标签）；默认不导出 `notes` 和三个 deprecated 字段。缺少元数据时仍可导出源码。
