# UI 焕新方案：Spectrum Workbench

## 结论

建议将现有“蓝灰单色工作台”升级为 **Spectrum Workbench（谱系工作台）**：保留桌面工具应有的秩序、信息密度和可扫描性，但用有限的语义色、焦点卡片、层次更强的表面材质，以及只服务状态变化的微动效，替代大面积单一主色和静态卡片堆叠。

这不是将产品改成装饰性仪表盘。算法模板、题目、代码和 AI 计划仍是第一层信息；视觉变化只帮助用户更快分辨“正在做什么、哪里需要处理、什么已经完成”。

## 已核验的参考

### Geist Design System

- [Geist Introduction](https://vercel.com/geist/introduction)：其公开设计系统强调一致性，并覆盖开发者工具需要的 Command Menu、File Tree、Code Block、Empty State、Toast 等组件。
- [Geist Colors](https://vercel.com/geist/colors)：公开页面采用多级色阶，并明确区分页面背景、组件默认/悬停/激活背景、边框层级和高对比文字。这比“所有卡片同一种蓝灰色”更适合长期运行的复杂工作台。

可借鉴：把颜色定义为状态与层级，而不是为每个模块随机加渐变。

### Linear / Raycast 的产品结构（设计语言参考）

- 左侧导航保持低对比，仅让当前上下文获得明确色块。
- 顶部搜索/命令入口是全局操作中心，而不是单独占一张大卡片。
- 详情区提供一个“焦点对象”（当前模板或题目），其余信息退居次级层。

可借鉴：以快捷键、密度和选中状态带来“专业桌面工具”感；不直接复制品牌颜色或页面。

### Motion 的使用边界

- [Motion for React transitions](https://motion.dev/docs/react-transitions)：项目已依赖 Motion，足以实现布局转场、渐入、列表重排和状态反馈。

可借鉴：只让进入、选择、加载、进度和完成等状态变化动起来；尊重 `prefers-reduced-motion`。

## 视觉系统

### 色彩角色

| 角色            | 建议                             | 用途                        |
| --------------- | -------------------------------- | --------------------------- |
| Canvas          | 冷白/雾灰 `#F5F7FB`              | 大面积背景，不抢信息        |
| Surface         | 半透明白 `rgba(255,255,255,.88)` | 面板与卡片                  |
| Primary         | 靛紫 `#5A55ED`                   | 选中、主操作、当前焦点      |
| AI / 成功       | 青绿 `#1AA68B`                   | 已完成、AI 可执行、健康状态 |
| 待确认          | 琥珀 `#F59E54`                   | 需人工判断、计划待确认      |
| 复盘 / 特别提示 | 柔粉 `#E979A8`                   | 低频强调，不用于错误        |
| 错误            | 独立红色 token                   | 仅用于失败与破坏性动作      |

规则：同一屏幕最多让主色加两种语义强调色同时显眼；代码区继续维持独立 VS Code 风格主题，避免与产品状态色混淆。

### 层级与材质

1. 页面背景使用极淡径向色光，制造空间但不制造“玻璃拟态”。
2. 侧栏使用低对比底色与清晰分隔线；选中项为浅靛紫底色，而非整条高饱和色带。
3. 详情页顶部做成“焦点带”：只在当前模板/题目顶端使用一次较强色彩。
4. 常规卡片继续使用实色 Surface、细边框和低阴影；不把每张卡片都做渐变。

### 动效预算

| 场景               | 动效                                 | 时长          |
| ------------------ | ------------------------------------ | ------------- |
| 导航/树节点悬停    | 颜色 + 2–3px 位移                    | 160ms         |
| 页面/详情切换      | 淡入 + 8–12px 上移                   | 220–280ms     |
| 列表筛选与关系添加 | 布局平滑重排                         | 220ms         |
| AI 处理中          | 进度条或扫描光，不使用无限大面积旋转 | 1.6–2.4s 循环 |
| 保存成功           | 一次短暂状态点亮/Toast               | 300ms         |

禁止：背景持续漂浮、每张卡片分别延迟入场、无意义粒子效果、用动效掩盖慢请求。

## 页面改造顺序

1. **设计 token**：把 `globals.css` 的颜色、边框、阴影、间距和状态统一为语义 token；先保证亮暗模式对比度。
2. **应用壳**：升级导航、顶栏搜索和工作区状态，加入更清晰的选中/悬停/键盘焦点。
3. **模板库**：将当前模板详情升级为焦点带 + 代码区 + 关联题目三段式；树保持克制。
4. **题目与 AI**：题目状态、关联数量和 AI 计划使用不同语义色；AI 计划进度只在任务存在时可见。
5. **细节验证**：每一步都在 1440×900、1280×720、亮/暗和减少动效条件下截图验收。

## 本次预览

独立预览页：[亮色方案](../prototypes/ui-refresh-exploration.html) 与 [暗色方案](../prototypes/ui-refresh-exploration-dark.html)。两者共享同一份页面结构与设计 token，避免把暗色主题做成另一套不一致的产品。

它演示了：多语义色、焦点模板卡片、低干扰模板树、AI 扫描状态、信息卡层级、悬停反馈和减少动效兼容。它不读取用户数据、不接入 Electron API，也不改动当前正式界面。

## 实施建议

确认方向后，建议先做“应用壳 + 模板库”这一条纵向切片，而不是一次性改所有页面。这样可以先让用户体验到明显不同的色彩层级与动效，同时不触碰 SQLite、模板文件、AI Provider 或 IPC 边界。
