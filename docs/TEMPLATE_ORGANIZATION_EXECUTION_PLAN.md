## 目标与默认取舍

分类以源码证据为主，采用一个主分类与多个辅助标签/实现变体。优先降低错误的明确建议；未知、复合、证据不足或判断冲突的模板进入复核。导入与已有模板整理共用规范分类规则。

AI 只产生草稿。正式模板库变更必须经过 Diff、用户确认、版本复检和可恢复应用；元数据、题目关联、原始文件和其他工作区不得被静默损坏。用户已确认的分类应锁定，新的冲突只产生复核建议。

源码评测集中的预期标签若由 AI 草拟，明确标记待人工校核；Mock 结果、样本路径映射通过、软件绿测均不等于真实模型准确率。

## 必须修正的分类风险

1. `reconcileBatchCategories` 的替换身份必须限定到模板/算法族，不能用跨组共享的泛化 categoryId 当全局键；冲突进入复核，不以自报最高分强行统一。
2. 全局摘要是初步提案，详细源码证据可以修订它；摘要/详细不一致、截断或证据不足必须显式呈现，不能把头尾源码当作完整实现。
3. 证据引用要在 Main 校验到源码位置；文件名、目录、注释不得直接决定类别。
4. 未知 ID 失败关闭，未知算法形成待确认类别提案；泛化分类不冒充精确分类。
5. 全局目录是上下文，不扩大当前批次可操作 ID；草稿与用户已确认事实具有不同可信状态。
6. 保存用户确认及来源版本，后续整理不得静默推翻；重新确认前不改正式分类或路径。

## 组合契约

- Main 拥有规范分类解析、路径计算、证据校验和复核判定；Renderer 不再单独制定批次归并结果。
- 暂存条目分别表达处理阶段、分类结论、复核状态和应用状态。跳过/失败/取消不伪装已分类。
- 会话保留工作区、源码哈希、分类规则/提示版本、全局事实版本和暂存版本。断点恢复校验旧事实是否仍有效；晚到响应不得覆盖新的人工编辑。
- 分类结果包括主 categoryId、候选、标签/变体、证据覆盖、复核原因和用户确认状态。具体契约以 S1/S3 集成后的 ADR 与 Zod 为准。
- 全库整理复用现有计划执行/备份体系；动态暂存导入复用 S1 恢复体系，不引入第二套互相竞争的正式数据写入入口。
