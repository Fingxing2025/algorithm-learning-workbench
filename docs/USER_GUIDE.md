# 用户指南

## 从零开始

1. 启动“算法学习工作台”。首次启动不会读取旧项目、预置模板或开发者个人数据。
2. 选择“创建空白工作区”，指定一个新目录；也可以选择已有源码目录，首次扫描只读，不会自动移动或改名。
3. 在模板库选择“新建模板”，粘贴源码或上传源码文件。源码就绪后即可使用“立即补全”，文件名可以暂时留空；没有配置 AI 时也能手动填写路径与算法卡片。
4. 在“题目”中新建题目卡片，填写题面、状态和备注，并手动关联一个或多个模板。
5. 如需 AI，在“AI 设置”添加服务并选择任务路由；“AI 管理”只用于执行文件审计和计划任务。

## 模板与题目

- 模板源码、工作区 SQLite、题目图片、关联、文件计划和撤销备份都保存在你选择的工作区
  文件夹中；工作区内的数据库只保存受控相对路径。
- 应用可读取 macOS 常见 UTF-8、带 BOM 的 UTF-8/UTF-16，以及 Windows 中文环境常见的 GB18030、GBK、CP936 源码。算法卡片会显示检测到的编码；编辑已有文件时保持原编码和 BOM。
- 从外部选择或批量导入源码时，原文件始终只读；界面会显示检测到的源编码，最终创建在工作区的新副本统一保存为 UTF-8，便于后续跨平台使用。
- 新建模板时，AI 只补全空白字段。若路径或元数据与手工内容不同，界面默认保留你的内容，并要求逐字段选择后才合并。
- 已有模板可在算法卡片中选择“AI 补全空白字段”；如需处理多份，使用模板库工具栏的“批量补全元数据”，搜索并选择最多 20 份模板。
- 已有模板补全会先展示发送给 AI 的内容范围，再逐份生成草稿。检查每份模板的建议并取消不需要的字段后再保存；已有非空内容和用户笔记不会被 AI 覆盖。
- 批量保存整批成功或整批失败。如果源码或元数据在草稿生成后被其他编辑修改，应用会拒绝写入并要求重新生成，避免覆盖较新的内容。
- 模板树会在显示层折叠单子目录，不会因此移动真实文件。
- 题目与模板是多对多关系；解除关系不会删除题目或模板。
- 题目图片存放于当前工作区的 `problem-assets/images/`，不会自动上传；只有执行题目 AI
  分析时才发送给当前视觉任务 Provider。
- 打开题目图片后默认按预览宽度显示；长图可在预览内上下滚动，也可切换“适合窗口”查看整图。Escape 会关闭并回到原图片按钮。

## AI Provider 与隐私

- Provider 由你自行配置，包括 Base URL、协议、模型、能力、超时和 API Key。
- “DeepSeek”预设会填写官方兼容端点和当前推荐的 `deepseek-v4-flash`；可按需改为 `deepseek-v4-pro`。
- “阿里云百炼”预设会填写 `qwen-plus` 并显示北京兼容端点模板；你需要把其中的 `<WorkspaceId>` 替换为自己的百炼工作空间 ID，其他地域使用控制台对应端点。
- API Key 使用操作系统安全存储加密；界面、SQLite 和日志不会回显明文。Linux 系统安全存储不安全或不可用时，应用会拒绝保存密钥。
- 题目分析会发送你输入的题面和选择的图片；模板分类会发送当前源码；已有模板补全会发送所选源码、相对路径、非笔记元数据和完整模板目录；总体文件 AI 管理会发送路径、结构化元数据和总量受限的源码片段。
- 已有模板补全不会发送用户笔记、绝对路径、API Key、题目正文或其他工作区数据；发送预览会列出 Provider、模型、模板数和排除范围。
- 使用 AI 前请确认界面显示的 Provider 和模型。自定义 Provider 由你信任；应用无法保证第三方服务如何保留或使用数据。
- 没有 Provider 或断网时，模板浏览、题目管理和手动关联仍可使用。

## AI 草稿与文件管理

- 题目 AI 分析只生成可编辑草稿。取消不会创建题目、图片或关联；确认后才入库。
- 文件 AI 管理先执行只读审计，再生成受限计划。AI 不能直接执行命令、覆盖源码或任意删除文件。
- 总体文件 AI 会把计划拆成多个小请求：常规每批最多 4 个详细候选，单批输出上限 4,096 Token；共享路径的重复/相似审计组会保持在同一批。发送预览会显示批数、单批输入、候选和输出上限；任一批失败都不会创建半份计划或修改文件。
- 每项移动、删除重复文件或元数据更新都可以单独取消；最终执行前会再次显示 Diff 和确认。
- 执行文件计划前会在当前工作区的 `.awb/file-plan-backups/` 创建备份。成功撤销后对应
  备份立即清理；未撤销的执行仍保留备份，以保证恢复能力。
- 文件计划、执行、撤销、历史删除和对应的撤销备份都归“AI 管理”负责；“备份与恢复”不再重复提供这些治理功能。
- 如果“备份与恢复”报告执行记录缺少撤销备份，可在检查详情选择“前往 AI 管理处理”。AI 管理只显示当前工作区的失效执行记录；切换到其他工作区后，列表和数据状态会一起切换。
- 失效记录默认不勾选。只有撤销备份路径符合应用受管格式且目录确实不存在的记录可以清理；路径异常、符号链接、非目录或不可读状态会显示“受保护”。确认清理只删除执行历史并保留父计划，不会修改模板、题目、关系、源码或仍有效的备份。
- 若预览后撤销备份重新出现，确认会整批取消并要求重新检查；应用不会把重新出现的备份当作清理对象。
- 如果文件在计划执行后被外部程序修改，撤销会停止并提示冲突，不会覆盖后续用户数据。

## 数据位置与备份

- 工作区文件夹是该工作区业务数据的完整容器。新建工作区通常包含：

  ```text
  工作区文件夹/
    workspace.awb.json
    templates/
    problem-assets/images/
    .awb/workspace.sqlite
    .awb/file-plan-backups/
    .awb/restore-preflight-backups/
    .awb/recovery/
    .awb/cache/
  ```

- 已有模板文件夹升级为工作区时，应用会先只读扫描并请求确认；确认后完整内容按原相对
  结构迁入 `templates/`。升级会拒绝符号链接、特殊文件和路径冲突，失败时自动恢复原布局。
- 只有 Provider、任务路由、语言/主题/布局和安全存储密钥属于应用级数据。macOS 通常位于
  `~/Library/Application Support/算法学习工作台/`，Windows 通常位于
  `%APPDATA%/算法学习工作台/`；这些全局设置不进入工作区备份。
- “备份与恢复”默认导出真正的单文件 `.awb-backup v2`，可以直接在 macOS、Windows、移动介质和网盘之间复制；不需要再手工压缩目录。
- 当前工作区便携备份固定深拷贝该工作区的模板源码与相对路径、过滤后的 SQLite 快照、题目图片和受控撤销备份；不再提供关闭源码的普通 v2 导出，也不包含其他工作区、Provider 配置、API Key 或安全存储密钥。
- 点击“选择备份并恢复”后会自动校验 v2 文件，并显示“备份内容来源 → 当前目标工作区”和数据数量。包原来属于哪个工作区不决定恢复目标：只要包正确，就恢复到此刻打开的当前工作区。当前目标保留自己的 ID 和名称，内容会被替换而不是合并。
- 恢复不再选择父目录，也不会创建或映射到另一个工作区。应用先完整备份当前工作区，
  再把包内模板相对路径、源码、题目、图片、关系、计划和执行深拷贝到当前工作区文件夹的
  受管位置。当前工作区的路径、名称和 UUID 不变；来源工作区、其他工作区和 Provider
  不变，恢复后修改当前目标不会影响来源。
- 当前版本只接受包含完整模板源码的单文件 `.awb-backup v2`；旧目录包、缺少源码的包和多工作区包会在只读校验阶段拒绝，不会修改当前工作区。
- 当前 v2 恢复如果异常中断，页面只在验证 journal、提交标记、预备份和文件指纹后显示安全处理入口。旧隔离数据不提供兼容操作。
- Provider 配置和密钥不进入工作区备份；恢复时应用中既有 Provider 保持不变，无需因为恢复当前工作区而重新配置。源码保持原始字节，不自动添加 BOM、转换 GBK/CP936、修改换行或静默重命名。
- 跨系统迁移后先重新启动应用，检查题目、图片、模板关系和源码；再从目标系统重新导出一份 v2 并在原系统验证，才算完成双向备份演练。
- V2 不支持从旧版项目迁移；版本升级仅通过 V2 自身的数据库 migration 原位保护现有 V2 数据。

## 当前发布限制

- 当前源码为 0.1.2；macOS arm64 候选会同时生成 SHA-256、SBOM 和隐私/架构证据，但本机没有 Developer ID 或 notarization 凭据，只能作为 unsigned/ad-hoc 预览，系统可能警告或阻止。
- Windows x64 NSIS 已配置原生 CI 候选构建和打包入口 smoke，但尚未在真实 Windows 主机完成安装、已有数据升级、快捷方式、权限和卸载保留验收。
- v2 单文件导出、校验、当前工作区原地恢复和内部 ID 重映射已经可用；macOS 自动化已验证，
  Windows CI 会运行同一真实 Electron 数据管理流程。真实 Windows 物理机的
  macOS→Windows→macOS 往返证据仍需在发布前完成。
- 正式公开发布前仍需平台代码签名、公证、Windows 实机证据和可信下载渠道。不要从聊天或非可信镜像接收证书、私钥或安装包。
