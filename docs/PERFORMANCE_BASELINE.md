- 基线提交：`0ef1afa docs: record native template close fix`

## 机器与运行条件

| 项目     | 值                                         |
| -------- | ------------------------------------------ |
| 机器     | MacBook Neo（Mac17,5）                     |
| CPU      | Apple A18 Pro，6 核（2 性能核 + 4 能效核） |
| 内存     | 8 GiB                                      |
| 架构     | macOS arm64                                |
| macOS    | 26.5.2（Darwin 25.5.0）                    |
| Node     | 24.18.0                                    |
| Electron | 43.1.0                                     |
| 运行次数 | 每个规模、每项指标 5 次                    |

Electron 启动每次创建新进程并等待真实主导航可见，属于进程冷启动；测试不请求特权清空 macOS 文件缓存，因此文件系统缓存保持机器的自然冷热状态。首次扫描使用新 SQLite/userData，重复扫描复用已建索引的同一测试 userData。基准运行期间未手工运行其他重负载任务。

Main/Vitest 指标的内存值是同一基准进程在该操作期间观察到的 RSS 峰值，包含此前已加载模块和夹具索引；Electron 启动指标统计 Main、Renderer 及其子进程树的 RSS。它适合比较同机、同命令的优化前后变化，不应当解释为单个函数的独占内存。

## 确定性夹具

夹具只创建在系统临时目录和测试 userData，测试结束递归清理；不会扫描或修改真实用户工作区，也不会进入安装包。规模如下：

|   模板 |  题目 | 图片元数据/文件 | 模板关系 |
| -----: | ----: | --------------: | -------: |
|  1,000 |   200 |              20 |      400 |
|  5,000 | 1,000 |             100 |    2,000 |
| 10,000 | 2,000 |             200 |    4,000 |

模板夹具包含多层目录、单子目录链、受控长路径/长文件名、中文/英文/日文/俄文/韩文目录、五种源码扩展名、完全重复与高相似源码。题目包含多标签、图片元数据和多对多模板关系。所有内容均由固定算法生成，不含个人数据。

## 基线结论

1. 无变化重扫与完整重扫工作量几乎相同；10k P50 甚至为 661.36 ms 对 649.10 ms，证实当前“全量 stat + 全量失效 + 全量 upsert”没有增量收益。
2. 题目列表和单题详情均随总题目/图片/关系增长；单题详情会重新构建完整列表，10k 夹具下 P50 分别为 148.50 ms 和 141.37 ms。
3. AI 候选检索逐模板读取元数据并全量构建分类/相关性输入，10k P50 为 557.61 ms，且同一进程 RSS 峰值达到 316.31 MiB。
4. 相似度基线在 5k 后没有继续线性增长，是因为现有实现只处理前 2,000 个模板、只让前 500 份源码参与相似度比较；这不是 10k 已优化，而是安全上限造成的无提示截断。
5. 模板树纯模型计算仍较小，但当前 IPC/WorkspaceSnapshot 会一次传输全部模板；真实 Electron 10k 启动 P50 为 2.68 秒、进程树 RSS 峰值约 615 MiB，后续仍需分页/懒加载边界。

## 隐私边界

基准 JSON/Markdown 只记录数据规模、时长、运行时版本和聚合内存。不得写入源码、题面、Provider 响应、API Key、绝对路径或真实工作区名称。脚本生成的工作区和 userData 都在临时目录，测试结束清理。
